# 7주차 — 검증 방문 아카이브와 랭킹 신뢰 신호

## 이번 주 목표

크루의 방문 기록과 공개 랭킹이 같은 서버 원장을 바라보도록 연결한다. 예약·방문 의향·레거시 체크인·자기신고 인원은 검증 방문으로 승격하지 않는다.

## 구현

- 기존 visit_events와 visit_participants를 유일한 검증 방문 원장으로 사용
- 크루 쇼케이스에 이벤트 단위 방문 아카이브와 장소별 요약을 함께 표시
- 방문마다 KST 방문일, 참여 인원, 검증 방식, 재방문 회차를 표시
- 공개 랭킹에 verified_visit_count, verified_revisit_count, trust_status를 추가
- 랭킹의 기존 활동 점수는 변경하지 않음. 실제 데이터가 부족한 단계에서 임의 가중치를 도입하지 않고, 방문 신호는 별도 투명 지표로 노출
- 검증 방문이 0건이면 숫자를 만들어내지 않고 “방문 데이터 쌓이는 중” 상태를 표시

## 품질 규칙

- status = verified인 원장만 아카이브·신뢰 신호에 사용
- 예약 완료·재방문 의향·과거 레거시 체크인은 집계에서 제외
- occurred_at은 UTC로 보관하고 visit_date_kst는 Asia/Seoul 경계로 산출
- 크루 방문은 같은 장소·같은 KST 날짜에 하나의 이벤트로 묶고, 참가자는 별도로 보관
- 참가자의 reported_party_size는 증거가 아니며, 2시간 내 독립 인증이 있어야 공동 방문이 verified가 됨
- 외부 공개 화면에서는 참가자 신원을 노출하지 않고 인원 수만 표시

## 검증

- 데이터 0건에서 빈 아카이브와 기록 대기 상태 확인
- 두 명의 동일 장소 공동 방문은 방문 1회·참가자 2명으로 표시
- 다음 날 재방문은 같은 장소의 2회차로 표시
- 레거시 place_checkins가 있어도 verified 방문 수를 증가시키지 않음
- 기존 PostgreSQL 동시성·KST 경계 테스트와 함께 CI에서 검증
