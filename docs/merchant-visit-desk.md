# 점주 방문 확인 화면 지원

4주차 PR #6의 재방문 지표·운영 점검은 main에 병합됐고 두 Vercel 배포가 성공했다. 이번 변경은 별도 [점주 콘솔](https://github.com/ymjo140/rendezvous-merchant)의 현장 QR·승인 대기 화면을 연결하기 위한 후속 작업이다.

## API와 손님 화면

- QR 발급 응답에 `server_time`을 추가한다. 점주 기기의 시계 차이와 무관하게 `expires_at`까지 남은 시간을 계산할 수 있다.
- 승인 대기 목록에 소유 매장 이름·서버 시각, 요청별 만료 시각과 현장 대조용 8자리 번호를 추가한다. 탈퇴한 멤버·삭제된 크루의 요청은 표시·승인하지 않는다.
- 손님 체크인 대기 화면에도 같은 요청 번호를 표시한다. 번호만으로 인증하지 않으며 이름과 실제 방문을 함께 대조한다.
- 점주 승인 입력 `expected_created_at`을 행 잠금 안에서 비교한다. 만료 후 같은 ID로 갱신된 요청을 이전 확인으로 승인하면 409다. 기존 입력 없는 호출은 호환을 유지한다.
- QR·승인·대기 응답은 `private, no-store`다. 인증 체계, 방문 기준, 혜택 차단과 중복 방지 정책은 기존 서비스를 사용한다.

DB 마이그레이션은 없다. 기존 테이블 권한 정리 제안을 실행하지 않는다.

## 검증과 적용

로컬 백엔드 145개와 링크 4개가 통과했다. PostgreSQL 12개는 CI에서 별도 실행한다. 새 테스트는 소유권, 손님/점주 코드 일치, 시간 경계, 두 명 승인 후 공동 방문 1회, 중복 승인, 요청 갱신에 대한 이전 확인 거절을 다룬다. 점주 콘솔은 DOM/계약 테스트 23개와 타입검사·빌드를 별도로 검증한다.

API 지원 변경 → 실제 API 버전/준비 상태 확인 → 점주 콘솔 순서로 적용한다. 최종 CI·병합·배포 결과는 각 PR에 기록한다. 콘솔 운영 절차는 [점주 방문 확인 문서](https://github.com/ymjo140/rendezvous-merchant/blob/codex/merchant-visit-desk/docs/visit-desk.md)에 있다.

2026-09-12 01:32 UTC 기존 keepalive 작업에서 Render 루트가 약 54초 후 HTTP 200을 반환한 기록을 확인했다. 이는 루트 연결 확인이며 특정 커밋·새 스키마·실계정 인증까지 검증한 결과는 아니다. [점검 실행](https://github.com/ymjo140/rendezvous/actions/runs/34665073214).

추가 운영 점검에서는 `/api/health/live`와 `/api/health/ready`가 모두 HTTP 404였다. main 코드에 두 경로가 등록돼 있으므로 현재 실행 중인 코드/경로가 기대한 배포와 다르다. 2026-09-13 추가 조회에서 루트와 `/openapi.json`은 200이지만 명세에 상태 확인·점주 QR·방문 승인 경로가 모두 없었다. 최근 방문 인증 API가 운영에 반영되지 않은 상태이며, 정확한 배포 커밋과 원인은 아직 확인하지 못했다. Render의 연결 저장소·브랜치·최근 배포 로그를 확인하고 API를 먼저 배포해야 한다. 이 확인 전에는 점주 콘솔 PR을 운영에 병합하지 않는다.

Render 설정 확인 시 저장소 `ymjo140/rendezvous`, 브랜치 `main`을 대조한다. 작업 디렉터리가 `backend`이면 시작 명령은 `python -m uvicorn main:app --app-dir src --host 0.0.0.0 --port $PORT`, 설치 명령은 `pip install -r requirements.txt`다. 저장소 루트에서 시작한다면 각각 `--app-dir backend/src`와 `-r backend/requirements.txt`를 사용한다. 현재 Render의 실제 설정은 연결이 없어 읽거나 변경하지 않았다.

실계정 두 명의 현장 방문·실기기 카메라/위치 권한·점주 화면 시각 검증, 파일럿 모집과 관찰은 남아 있다.
