# 3주차 — 크루 미션·방문 피드백·화면 연결

## 구현 범위

- RDV-07: 저장 미션은 **내가 이 크루 폴더에 직접 저장한 장소**만 집계한다. 개인 저장·다른 크루 저장·게시물·리스트 복사·가져오기는 제외한다.
- 리스트 담기는 원본 폴더/크루, 도착 폴더/크루, 실행자, 실제 추가 수, UTC 시각을 `list_copy_events`에 기록한다. 현재 내가 속하지 않은 크루의 공개 리스트를 이 크루로 담은 기록만 인정한다. 기존 `list_saves`는 사회적 담기 수로 유지하며 미션에 소급 반영하지 않는다.
- 동일 원본을 같은 크루로 다시 담으면 기존 도착 폴더를 갱신한다. 추가 0개는 진행으로 인정하지 않는다. 다른 도착 폴더로 다시 복사하거나 도착 폴더를 삭제해도 같은 원본의 주간 완료를 재발급하지 않는다. 포인트/원작자 보상은 지급하지 않는다.
- RDV-08: 미션별 행동 버튼 → 장소 검색/크루 저장/외부 리스트 담기/방문 인증 → 서버의 진행 기록 확인을 연결한다. 방문·메뉴·단골 미션은 2주차 공동 방문 기준을 그대로 사용한다.
- 새 방문 참가자는 방문 시각으로부터 3시간 후 재방문 질문에 답할 수 있다. 공동 방문이 두 번째 멤버를 기다리는 중이어도, 이미 현장 인증한 본인의 개인 후기는 가능하다. 다른 멤버의 참가 기록으로 대신 답할 수 없다.
- `verified_visit_feedback`은 방문·사용자당 한 건이다. 개인/모임 답변을 엄격한 boolean으로 받고, 별점 후기는 먼저 답한 방문에 한해 한 건만 작성한다. 탈퇴한 크루에 대한 모임 답변과 클라이언트가 보낸 임의 크루/예약 연결은 허용하지 않는다. 이전 체크인은 본인 소유와 시간/장소를 검사해 기존 후기 경로를 유지한다.
- 새 참가자의 현장 인증은 장소·KST 날짜당 한 번 개인 취향 신호에 반영한다. 방문 질문과 후기 응답은 취향 캐시를 갱신한다. 과거 자기 신고 체크인은 인증 방문 신호로 계산하지 않고 기존 저장·예약·후기 의향은 유지한다.
- 공개 배지의 재방문 **의향**을 실제 재방문처럼 표현하지 않는다. 동일인의 최신 답변을 사용하고 모임 추천은 사람 수로 표기한다. 비공개/리스트만 공개 크루의 모임 답변은 공개 집계에서 제외한다.
- RDV-09: 이웃 크루와 예전 `/groups/{id}`는 `/crew/{id}`로 모은다. 크루 상세와 주방이 같은 쇼케이스를 사용한다. `/home-next` 초대 쿼리를 보존하고 외부 URL로 바뀌지 않게 각 경로 조각을 인코딩한다. 체크인 로그인 후 선택 크루/예약을 유지한다.
- 크루별 요청은 전환 시 데이터와 오류를 초기화하고 이전 응답을 폐기한다. 포커스 복귀/활동 후 진행을 새로 조회하며 실패는 빈 기록 대신 재시도 안내를 표시한다. 후기 저장 실패 시 입력을 유지한다.
- RDV-10 시작: 서버 요청별 임의 request ID, 경로 템플릿, HTTP 상태, 응답 소요시간을 구조화 로그로 남긴다. 실제 방문 ID·쿼리·토큰·본문은 로그에 넣지 않는다. 운영 대시보드/알림 기준과 사용자 관찰은 후속 범위다.

## 마이그레이션·배포

2주차 스키마 적용 후 `supabase/migrations/20260910124519_missions_feedback.sql`을 적용한다.
새 테이블 2개와 취향 캐시 시각만 추가한다. 이전 데이터는 변경하거나 인증 방문으로 승격하지 않는다.
RLS를 활성화하고 anon/authenticated의 테이블 권한을 회수한다. 서버 DB 역할은 소유자/승인된 서버 역할이어야 한다.

```sh
python backend/scripts/migrate_week3.py --apply
python backend/scripts/migrate_week3.py --check
```

DB → API → 프론트 순서로 배포한다. 이 개발 PR의 운영 마이그레이션/병합은 아직 수행하지 않았다.
프론트 프리뷰를 확인할 때는 같은 버전의 스테이징 API를 연결해야 한다.
이전 API로 롤백하더라도 새 출처/후기 테이블은 유지한다.

`docs/pending/restrict-server-tables.sql`은 기존 테이블의 별도 보안 변경 제안이다.
자동 승인 검토가 운영 적용을 거절했으므로 **미적용**이며 위 마이그레이션 스크립트는 이를 실행하지 않는다.

## 검증과 남은 확인

- SQLite/API 회귀: 117개 통과. 출처·크루 범위·자기 크루 제외·주간 경계·후기 소유·시간·중복·캐시·개인정보 없는 로그를 검증한다.
- PostgreSQL CI: 2주차 7개에 동시 후기/별점, 동시 리스트 복사, 신규 제약/RLS 3개를 추가했다. 실제 운영 DB에 테스트 데이터를 넣지 않는다.
- 프론트: 링크 보존/외부 리디렉션 차단 4개 테스트, lint/TypeScript 및 production build.
- 실제 계정으로 모바일 2명 체크인 → 3시간 후 후기 → 크루 전환/재진입 흐름과 사용자 5명 관찰은 아직 수행하지 않았다. 별도 점주 콘솔의 QR 표시·직원 승인 화면은 연결이 필요하다.

참고: [Supabase RLS 및 grants](https://supabase.com/docs/guides/api/securing-your-api), [PostgreSQL 행 잠금](https://www.postgresql.org/docs/current/explicit-locking.html).
